# Quishpi and MedicalProcessInstruks are split like PET

Both new datasets use PET's split (a seeded 80/20 sentence split, then the bootstrap sentences) so their results are comparable with PET's. Quishpi has no test split of its own. It follows PET even though 13 of its 18 texts are PET documents, and even though a document-level split would keep the sentences of one text out of both sides. MedicalProcessInstruks does ship a test file, but it is one guideline of 28 sentences that misses several types, so its train and test files are joined and re-split rather than used like CoNLL-2003's test split.

Quishpi's brat offsets are read as UTF-8 byte offsets, because that is how the annotations count past the one non-ASCII character. Every span must then match its text exactly, instead of being realigned by search, and where spans overlap the longer one keeps the words. MedicalProcessInstruks publishes integer tags without names. Its types are tagged by their begin id rather than guessed from their words, and only the 19 types that occur are kept. The dataset's authors later shared their label definitions, which name every type (T03 is a single activity, T41 an actor). Those names are only displayed, through `MEDICAL_TYPE_NAMES`: the tags stay `B-T03` … `I-T43`, because saved runs record their predicted tags by id. The authors' simplified schema, which merges inclusion-response into inclusion and condition-response into condition, is not applied, as it would change the labels of runs already made. Van der Aa's DECLARE constraint collection is not used: it names activities as normalised phrases with no word spans, so any NER labels would have to be guessed.
